# 网页仪表盘（服务端 0.5.0 / 客户端 0.8.1）

2026-10-29 已部署，数据库 schema v5。入口：https://YOUR_SERVER_HOST/codex-usage/ 。

## 使用

使用现有遥测只读凭据登录；这不是 Codex 登录凭据或 OpenAI API Key。采集器底部“网页凭据”及右键“网页仪表盘登录…”已提供内置入口。点击“复制用户只读凭据”后，程序校验服务器返回的读取范围必须为当前 Windows 用户，管理员范围或其他用户的凭据将被拒绝。校验通过后仅将 read_token 交给界面写入剪贴板，再点击“打开仪表盘”粘贴登录。凭据通过私有子进程管道传递，不写入状态文件或日志，不需要单独运行脚本。网页凭据仅存当前页面内存，刷新或断开后清除，不写入 URL、localStorage 或请求日志。

- 按全部账号（含未知归属）或具体账号查询。
- 名称优先级：浏览器本地备注 > 服务器同步展示名称 > 匿名账号键。名称后附加匿名键尾部，区分同名账号。
- 最近 24 小时按小时聚合；近 7/30/90 日按北京时间自然日聚合，包含今天。
- 统计输入、输出、缓存输入、推理输出和总量，支持图形/表格切换、指标选择、CSV 导出。
- 点击刷新读取最新用量和账号名称。本地备注留空后恢复同步名称。

累计表示账本已采集用量，并非完整官方账单或额度百分比；页面始终标记部分覆盖。缓存输入和推理输出为子集，不重复计数。没有增量的时间桶为已采集增量零，不表示日志完整覆盖。

## 用户与管理员如何登录

| 凭据类型 | 可见范围 | 获取方式 |
|---|---|---|
| 用户级 read token（principal） | 绑定 Windows 主体已上传的账号、统计、趋势及其展示名称 | 采集器底部“网页凭据”或右键“网页仪表盘登录…” |
| 管理员 read token（tenant） | 同一租户全部已接入用户与账号 | 管理员保管的初始交付文件，默认 `/opt/codex-usage-monitor/private/client.json` 的 read_token；可用性及范围以服务器校验为准 |
| 设备 write token | 设备授权的上报及名称写入，不用于仪表盘读取 | 独立安装凭据内部使用，不从网页入口复制 |

只读 token 是随机访问令牌，不承载用量记录或 Codex 登录密码；数据库保存其校验哈希。完整本机凭据配置含读写令牌等字段，并以当前用户 DPAPI 加密保存在 `client.credentials`。内置入口只返回 read_token，不导出完整配置。

读取权限绑定凭据，不取决于网页所在电脑。把同一用户 token 用在另一台电脑，仍只能查看原绑定 Windows 主体的数据；不同电脑上的同名 Windows 用户不会自动合并。管理员需换用 tenant 级 read token 登录同一个网页，选择“全部账号”或具体账号；页面“全部账号”不会扩大普通用户权限，也不包含未接入、未采集的数据。不能通过修改页面筛选器、上传姓名或普通 token 将自己提升为管理员。

## 数据接口与权限

`GET /v3/usage/trend?period=24h|7d|30d|90d&account=<可选匿名账号键>` 使用原 read 凭据，沿用 tenant/principal 作用域及撤销规则。范围最多 90 日；数值以字符串传输，前端以 BigInt 处理，表格与 CSV 保持大整数精度。查询区间为半开区间，首尾时间桶可能不完整。

HTML/CSS/JS 与接口同源，无第三方 CDN；页面设置 CSP、no-store、nosniff、no-referrer。`/health/live` 保留 JSON 存活状态。

## 名称同步

客户端通过独立 `POST /v3/accounts/display-names`，使用既有设备 write 凭据发送 `profiles: [{account_key, display_name}]`。只同步当前登录账号有效名称，跳过空名称和“未读取到账号名称”。头像、缓存路径、额外邮箱字段及 Codex 登录凭据不发送。名称不作为认证、归属或去重依据。

同步异步进行，名称变化后发送；每条独立确认，失败约 30 秒后重试，一个账号失败不阻塞其他账号或用量采集。确认结果存于本机 `display-name-sync.json`，重启不重复发送相同名称；状态文件 `display_name_sync` 提供错误与已确认账号数，不将名称写入日志。

`account_display_names` 按租户、账号、Windows 用户保存名称及来源设备。设备须登记身份，且已有本用户的数值归属或额度观察记录，才可登记该账号名称。同名重传不改变更新时间，不同用户分别保存。`GET /v2/identities` 保持原 accounts 键列表，并增加 account_display_names 映射。受限 read 凭据仅返回自身名称；租户级 read 凭据可见同账号最近变更的展示名称。名称来自客户端，并非官方实名认证。

- 真实 PostgreSQL 18.6 独立库：61 项通过，19.597 秒，包含并发、权限、账号过滤、跨日、90 日上限、24 小时半开区间、零桶、2^53 以上数值、名称变更/重复/撤销及迁移测试。
- 客户端：152 项 Python 测试、20 项周期显示检查及完整 WPF 构建通过。
- 浏览器本地同一代码验证了登录失败、凭据清除、账号/范围/指标切换、图形/表格、CSV、390px 窄屏、名称更新、备注覆盖与清空恢复。预览使用示例数据。
- v4 备份恢复并重复迁移 v5，六张原表指纹保持一致。正式迁移保留 1,161 条事件、1,114 条增量、122 条周期、123 条周期汇总、174 条观察和 2 条边界状态。
- 真实 HTTPS 页面、静态资源和健康接口均 200，未授权趋势请求 401；真实展示名称匹配本机，同步无错误。
- 16:42 左右近 7 日快照总量 95,145,003、748 条增量，与原始账本四项数值逐项一致；两个当前额度周期同样对账通过，之后正常增长。

内置浏览器公网导航超时，生产浏览器页面未记为实机通过；本机独立 HTTPS 证书验证及接口对账通过。跨真实 Windows 用户、跨机器及负载实机验收仍未完成。

## 升级与回滚

先备份，明确构建并测试 0.5.0 镜像，暂停 api 后迁移 schema v5 并应用最小应用角色权限，再启动服务端，最后更新客户端。备份为 `backups/pre-upgrade-0.5.0.dump`、`backups/pre-switch-0.5.0.dump` 和 `private/pre-upgrade-0.5.0-source.tar.gz`。迁移只新增名称表，旧数值身份不变。回滚使用 0.4.0 镜像及对应源码，保留新增表和上线后账本数据。
