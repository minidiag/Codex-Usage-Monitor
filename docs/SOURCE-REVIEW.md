# 暂停来源的核实与恢复

点击悬浮窗底部“部分来源暂停 · 点击核实”，或右键选择“核实暂停来源…”。采集器会检查本机日志和服务器的原基线，显示：

- 每份日志的完整路径、检查点数量、起止时间；
- 是否包含原基线，能否逐条复现本机已保存的事件；
- 与可匹配来源的共同检查点和顺序关系；
- 服务器尚无该流、基线一致、基线不同或连接失败；
- 可恢复条件和当前不能恢复的原因。

“恢复可证明的重复副本”只处理完整序列相同或短文件为完整文件同序列前缀的情况。文件更大、更新时间更晚、会话 ID 相同都不是自动信任依据。

对于内容不同但其中一份可以复现原基线和全部历史记录的情况，核实窗口允许明确选择“选择此来源并恢复”。确认框列出所选路径及将被排除的其他文件数。其他文件保留在磁盘，但不再参与该流的采集，不把它们的用量混入所选来源。新发现的不同文件仍需要重新核实。

恢复前会重新读取文件并核对指纹、历史事件和服务器状态；文件变化、记录冲突、计数异常、服务器无法核实或基线不同都会拒绝恢复。操作保留原基线、事件 ID、已确认记录及原日志；使用 SQLite 在线备份保存操作前账本，并在同一事务内记录来源选择和排除规则。

核实窗口中的历史记录显示选择时间、所选路径和备份位置。需要改选已排除日志时，先重新核实；如果该流目前没有暂停，请先由维护人员检查后处理，不直接修改数据库。文件移动后若不能验证原基线，仍会暂停并再次提供核实入口。

报告位于当前安装对应的用户状态目录：`state/source-review.json` 与 `state/source-review.md`，审计记录保存在本地账本 `source_review_audit`，操作前备份位于 `state/source-review-backups/`。这些文件含本机路径与用量定位资料，仅在本机使用，不上传阿里云，不宜公开。

命令行也可向正在运行的采集器提交请求：

```powershell
& 'C:\Path\To\python.exe' -m client.source_review
& 'C:\Path\To\python.exe' -m client.source_review --action auto
```

明确选择某份来源时，先检查本地 JSON 报告中的 `stream_id` 和 `source_id`，再使用 `--action resume --stream <stream_id> --source <source_id>`。命令行同样需要新鲜报告，并经过后台相同的核实与审计流程。全局暂停采集期间允许核实；即使来源恢复，也需继续全局采集后才会上传。
