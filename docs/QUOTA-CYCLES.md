# 额度周期统计（客户端 0.8.1 / 服务端 0.5.0）

2026-10-29 当前部署为 schema v5。周期识别与查询算法于 0.4.0/schema v4 引入，0.5.0 保留该算法并新增网页与名称元数据；下面迁移和对账数量保留其对应版本快照。

## 当前周期和历史查询

5 小时和每周额度由 `GET /v3/usage/quota-current?account=...&principal=...` 分别返回 primary、secondary 当前槽位。查询只按当前状态指向的周期 ID 取值，不扫描有限条历史，因此每周历史无法挤掉 5 小时周期。

`GET /v3/usage/quota-history?account=...&principal=...&bucket=primary|secondary&limit=...&before=...` 按桶独立分页，按实际起点倒序，下一页使用返回的 next_before；账号和用户权限规则与当前查询一致。旧 v2 历史接口保留，活动周期优先、其余按起点倒序，主要供旧查询工具使用。

## 观察与周期识别

`POST /v3/usage/quota-observations` 接收匿名账号、桶、周期长度、计划重置绝对时刻和观察时间。旧 v2 POST 也进入相同识别流程。周期观察不携带官方百分比、头像、明文名称或 Codex 登录凭据；展示名称使用独立接口同步，见 [网页说明](DASHBOARD.md)。

原始观察存入 quota_boundary_samples，当前识别状态存入 quota_boundary_states。客户端按账号、桶、观察时间持久化并去重，上传成功后确认发送；重复缓存不充当新的稳定证据。单条冲突单独隔离，其他观察和当前查询继续处理。

周期使用独立生成的 ID；计划重置时刻是属性，±1 秒差异按同一边界处理。新候选需至少 3 次不同时间观察，且首末跨度至少 60 秒。移动边界只更新候选，不持续生成周期。未到期或与旧周期重叠的新边界进入待核实，不自动截短原周期；旧周期到期后，稳定且不重叠的新边界才能建立下一周期。迁移采纳仍有效的旧周期 ID，保留全部历史碎片与数值；异常历史只生成候选核查报告。

稳定次数和 60 秒是本程序采用的识别策略，并非官方关于额度重置的保证。持续异常的边界需要人工核查。

## 统计与界面

累计包含当前 Windows 用户、所选匿名账号和该额度周期内已采集并上传的输入加输出 Token；缓存输入及推理输出为子集。区间为 `[重置时间−周期长度, 重置时间)`，晚到的有效事件仍按原账本补算，重复上传不增加数值。上方滚动 5 小时及自然日、周、月卡片保持各自口径。

界面分别显示边界确认中、边界待核实、额度需刷新、等待新周期、等待周期数据；未知数据不补成 0。官方观察超过 90 秒标记过期，查询缓存超过 35 秒变暗。观察来源随官方额度刷新，当前账号周期查询约每 10 秒一次；5 秒日志扫描不代表官方额度观察每 5 秒更新。保留部分覆盖标记，不推测启用前或未知归属的用量。
