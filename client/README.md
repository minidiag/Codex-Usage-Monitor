# Windows 采集器与用量悬浮窗

当前版本为 0.6.0。桌面入口为 **Codex 用量统计**，当前用户登录时自动启动。窗口固定显示当前 Windows 用户的用量，标题为 Codex，居中显示 ChatGPT 真实头像和明文账号名，通过下拉列表切换 Codex 账号。匿名键只用于后台统计，明文显示资料不上报。详见 [本地头像账号界面](../docs/LOCAL-ACCOUNT-UI.md) 与 [新用户接入方式](../docs/MULTI-ACCOUNT-OPERATIONS.md)。

## 使用

首次安装、新 Windows 用户接入和服务端部署见 [统一操作步骤](../docs/INSTALL-AND-DEPLOY.md)。

- 双击桌面 **Codex 用量统计** 可打开窗口，也会确保后台采集器启动。
- 点击 × 仅关闭窗口，后台继续采集；再次双击桌面入口即可打开。
- 右键可暂停/继续采集和同步、取消置顶，或停止采集并退出。
- 暂停后恢复会补读日志中尚未处理的检查点，保留原事件时间；暂停不删除数据。
- 鼠标停在周期数字上可查看输入、缓存输入、输出和推理输出。总量为输入加输出，两个子集不重复相加。
- **USAGE · 账户额度** 在“5 小时额度”“每周额度”旁用括号显示当期累计 Token（仅当前 Windows 用户和所选账号）；周期定义和分项累计保存在服务器，见 [周期统计说明](../docs/QUOTA-CYCLES.md)。同时显示 Codex 返回的剩余比例。鼠标停在倒计时上可查看北京时间的具体重置时刻。
- **本用户活跃会话** 显示标题、模型和当前 Windows 用户已确认采集的会话分段；较多会话可在列表内滚动。
- 标题栏居中的头像/姓名可下拉选择账号、“全部账号”或“未归属用量”，都限定当前 Windows 用户。切换时周期、活跃列表和额度一起刷新。

窗口显示服务器已确认账本的汇总，不将待上传数据混进数字。离线时保留最后一次成功查询，并显示异常或待上传状态。数字完整显示并自动缩放，不将百万级用量仅保留一位小数。

原版 Yxianshe/Codex-Monitor v2.1.4 已按用户要求卸载，包括已核对的便携安装目录和其中的快捷方式。未发现外部自启动或卸载注册项；本应用不依赖原版程序。OpenAI Codex 本体、本地会话和本项目统计数据库均保留。

## 活跃会话 Token

参照 [Yxianshe/Codex-Monitor](https://github.com/Yxianshe/Codex-Monitor) 的索引加日志判定方式实现，不需要重新安装原版程序。每约 5 秒，以只读方式读取每个 `CODEX_HOME` 最近的 `state_*.sqlite`（包含 WAL 中的已提交更新），选择最近 12 个未归档会话。

- 标题优先采用 `session_index.jsonl` 的友好名称，回退到索引标题第一行，最长 80 字；模型和推理强度优先从近期日志读取，回退索引。
- 日志最近的任务开始事件表示活跃，完成或中止表示结束；明确结束的会话即使刚修改过日志也不显示。没有明确任务事件时，采用最近 10 分钟内写入的日志作为“近期活动”，并在模型旁标记。
- **0.5.0 的数字来自本机已采集检查点增量，仅包含确认属于当前 Windows 用户的分段，并按账号选择过滤。** 它不使用 `threads.tokens_used` 的跨用户整段历史，也不额外加进四周期账本。未知值显示“—”，真实零显示 0，大整数完整显示。
- 与原版相同，每个目录只检查最近 12 个未归档会话；不保证发现更早的后台任务。异常退出且未写结束事件的任务可能保留活跃状态；本功能不等同于操作系统进程检测。
- 暂停时不继续读取；状态超过 35 秒、采集停止或索引失败时，旧列表变暗并标记“需刷新”。部分日志不可读时显示“部分可读”，不把读取失败当成没有活跃任务。
- 标题、原始 UUID 和会话详情只保存在本机 `status.json` 供窗口显示，**活跃会话列表不上传阿里云**。遥测仍只上传原有匿名数值白名单，不读取或上报对话正文。

日志反向扫描上限为 16 MiB，支持跨块 UTF-8 长记录，未写完的一行等待后续刷新。Windows 扩展路径与普通路径统一处理，拒绝越出配置数据目录的日志路径。索引缺失或格式不兼容时不会创建、修复或修改 Codex 数据库。

## 剩余额度与重置倒计时

额度来自本机官方 Codex `account/rateLimits/read` 只读接口，复用当前 Codex 登录。优先选择 `rateLimitsByLimitId.codex`，不存在时采用兼容的 Codex 单桶视图。百分比按 `100-usedPercent` 计算并限制在 0–100；按接口实际返回的周期标注标签，不假定所有主要窗口都为 5 小时。字段含义见 [OpenAI Docs：Codex App Server](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)。

- 约每 30 秒异步刷新一次额度，窗口每秒计算重置倒计时；读取超时不阻塞日志扫描和 Token 上传。
- `resetsAt` 按 Unix 秒解释，用北京时间显示具体重置时刻；不通过 Token 累计量估算额度。
- 额度数据超过 90 秒后不再显示为当前可用比例；到达重置时刻先显示“等待额度刷新”，不会自行变为 100%。
- 缺失的剩余比例显示“—”；没有重置时间时显示“重置时间未知”。近期缓存读取失败时会明确标记缓存。
- 暂停采集和同步时，也会暂停额度刷新；旧额度最终显示过期。恢复后重新查询。
- 只初始化本机接口并读取额度，不创建会话、请求模型、重新登录、注销或消耗重置权益。
- 剩余百分比、登录凭据和重置权益信息不发送到阿里云；0.6.0 会上传匿名账号的周期边界元数据，以便服务器保存当期 Token 累计。接口原始响应和认证内容不保存。

账户额度通常覆盖账户的多个设备；四周期 Token 统计只覆盖本采集方案已接入的来源。最近 5 小时 Token 是滚动窗口，官方额度则使用接口给出的窗口和重置时间，两者不能相互换算。当前接口没有提供可换算的“剩余 Token 数”。

## 统计范围

**从本次启用的基线开始累计，未导入更早历史。** 启用时间持久保存在本机数据库中；重启应用和 Windows 都不会重新开始累计。第一份本机基线建立于北京时间 2026-10-26 00:12:37。已有会话首次读到的最后累计检查点作为 capture_start 基线，不将其历史总量归到今天。

当前适配常规 `event_msg/token_count` 累计检查点及活动 `turn_context` 模型。扫描 Windows 当前用户 `CODEX_HOME`（默认 `C:\Users\<USERNAME>\.codex`）下的 `sessions` 和 `archived_sessions`。本机已核对 2 份日志的实际结构，并接入 2 条匿名流。

压缩补充用量、压缩文件 `.jsonl.zst`、子代理继承前缀和未知来源尚未全面适配。子代理/分叉来源采取保守跳过，缺失组件不补零，累计值重置或顺序异常暂停对应流。当前窗口与服务端正确显示 **部分覆盖**，不能把这些数字当作全账户完整账单。WSL 和其他用户目录不在默认范围。

新发现的会话同样先建立捕获基线，因此首次已完成请求可能属于未覆盖起始段；不会声称首个请求之前已完整覆盖。需要完整历史导入时应另行验证日志适配并重建账本，不能直接把旧总量加到当天。

## 工作方式

- 每 5 秒发现和扫描变化的日志，只有数值检查点被规范化和保存。
- SQLite WAL、FULL 同步，同一事务更新文件游标、流序号和待传记录。队列持久化，断网/重启后补传。
- 每批最多 500 条、约 500 KiB，每轮最多发 4 批；10 秒刷新服务器汇总，60 秒心跳，窗口每秒读取本地缓存并更新倒计时。
- HTTPS 直连 `https://YOUR_SERVER_HOST/codex-usage`，不使用环境 HTTP 代理，不跟随重定向，正常验证服务器证书。
- 不上传对话正文、标题、文件路径、原始会话 UUID、Codex 登录凭据或匿名化密钥。上传字段遵循服务端白名单。
- 设备和租户遥测凭据使用当前 Windows 账户 DPAPI 加密，服务端只存凭据哈希。其他机器不能直接使用本机加密文件。
- 流 ID、锚点和事件 ID 由共享匿名化密钥 HMAC 生成；设备身份不进入去重键。相同格式的跨设备复制需定位服务端共同基线后使用相同序号，定位失败就暂停，避免重复累计。
- 已确认的数值检查点继续留在本机，以便审计和服务器缺段后的重放。当前没有自动历史清理策略；待传上限 50,000 条、本地数据库 500 MiB 时停止继续推进来源游标并提示。

数值账本仅保存数值、模型、事件时间、匿名标识和必要的文件游标。活跃列表另外在本机状态缓存中保存标题与原始会话 ID，供窗口展示；它们不会进入上传队列或服务器请求。运行日志仅记录状态码和错误类别，不记录请求、响应正文或令牌。

## 文件和维护

0.4.0 起每个 Windows 用户独立保存运行状态。下表的 `用户目录` 为 `%LOCALAPPDATA%/CodexUsageMonitor/<项目安装标识>`；EXE 仍放在项目目录。当前用户的旧账本和凭据已迁移并保留备份，不要继续操作旧路径来暂停新版程序。

| 路径 | 用途 |
|---|---|
| `用户目录/state/collector.sqlite3` | 本机游标、基线、数值检查点、匿名归属和待传队列 |
| `用户目录/state/status.json` | 无凭据状态、服务器查询缓存及仅本机的活跃会话列表 |
| `用户目录/state/control.json` | 当前用户暂停状态和筛选 |
| `用户目录/state/agent.log` | 采集异常状态；轮转日志 |
| `用户目录/state/quota-cache.json` | 首个目录的本机额度缓存；其他目录在 state/quotas |
| `.local/client/CodexUsageMonitor.exe` | Windows 自带 .NET Framework 构建的原生 WPF 窗口 |
| `用户目录/client.credentials` | 当前 Windows 账户加密的遥测凭据 |
| `用户目录/state/local-profiles.json`、`state/avatars/` | 本机明文名称与头像缓存，不进入遥测或部署包 |

运行依赖为本项目已有 Python 3.12 环境（优先 `.local/venv`，其次用户安装的 Python312）及 Windows .NET Framework。前端不需要 .NET SDK 或浏览器。请保留项目路径和运行环境；移动项目后重新构建窗口、安装快捷方式和自启动。

手动启动后台与窗口：

```powershell
& 'E:\Codex\Codex-Usage-Monitor\client\Start-UsageMonitor.ps1'
```

只启动后台，加 `-NoWindow`。完全停止：

```powershell
& 'E:\Codex\Codex-Usage-Monitor\client\Stop-UsageMonitor.ps1'
```

取消登录自启动：

```powershell
& 'E:\Codex\Codex-Usage-Monitor\client\Remove-Startup.ps1'
```

修改前端后运行 `client/Build-Window.ps1`，先关闭现有窗口再构建。快捷方式直接指向原生 EXE，不需要改变 PowerShell 执行策略。它是当前用户后台程序，不是系统服务；若采集器异常退出，可双击桌面入口重启。

不要删除数据库或随意更换 identity_key，否则需要重新采用远端基线。上传凭据失效时应重新交付；累计值重置、来源校验失败和服务端 409 冲突应先核对源日志，不能通过随机更换流 ID 来绕过去重。
